# Accepted quest generation

Auto-do builds a fresh C# script for one live accepted quest. It uses current objective IDs, quantities and reward choice, checks inventory and bank, resolves acquisition steps, compiles the script, and runs a single turn-in. A matching community bot is optional.

Discovery uses item/reward wiki backlinks, followed by a bounded exact-name web search when no backlink is available. Search results only provide candidate wiki pages. The resolver checks the selected quest section, objective names and quantities, monster drop backlinks, level variants and map names before producing a route. It supports monster drops, linked clickable items and collection arrows with a documented quest location. Permanent material pages are also followed through their monster-drop links, cross-checked against the monster’s normal Items Dropped list. This fallback works without a matching quest page and remains available if web search fails. Temporary source failures are retried twice automatically. Local literal routes remain an additional source; a generic KillQuest route is never assigned to a permanent item.

For clickable items, the generated script joins the documented map and invokes map inspection. The bundled FFDec decompiler reads the game's current map SWF. The parser extracts literal pickup calls and quest-bound button metadata, ignoring comments and quoted examples. It selects a unique quest-bound pickup, or a unique unconditional pickup. It does not guess IDs or try an ambiguous set of buttons. Actual inventory ID and quantity must change before the next step or turn-in. Map downloads and decompilation have size/time limits; stopping cancels decompilation. Java is required (the same OpenJDK dependency used by build-flash.sh); on macOS the runtime detects Homebrew OpenJDK automatically.

Bank loading retries and can recognize a complete bank snapshot if its event was missed. An unknown bank is never treated as empty. If it remains unavailable, free quest drops/pickups can run with a visible notice; shop purchases remain blocked. Known banked materials are retrieved instead of farmed.

Planning can be canceled before script launch. Quest state is revalidated after research. Incomplete routes, ambiguous pickups, failed item acquisition and unavailable sources report a blocker rather than claim success. Arbitrary quest chains, dialogue puzzles, dynamic shop-ID discovery and every possible wiki format are not yet supported. This is structured source discovery and code generation, not an LLM that can reason through any game mechanic.

Validation includes independent wiki fixtures for quests 1489 and 4498, no-reward discovery, multiple monster variants, collection locations, bank snapshot completeness, canceled planning, and an authored Flash fixture compiled and decompiled with FFDec. The generated decoder script is also compiled against the installed CoreBots library. These checks do not substitute for a live server quest completion.
