# Accepted quest generation

Auto-do builds a fresh C# script for one live accepted quest. It uses current objective IDs, quantities and reward choice, checks inventory and bank, resolves acquisition steps from wiki/guides, compiles the script, and runs a single turn-in. Community C# quest bots and verified-route tables are not required.

Discovery starts from the current map’s wiki quest list, then item/reward backlinks, then a bounded exact-name web search (Google, then Bing). Search results only provide candidate wiki pages. The resolver reads the selected quest section, objective names and quantities, “Dropped by” monsters, click/walk pickups, and the documented quest location. A quest-page monster name plus that map is enough to hunt — a matching monster-page backlink is optional, so farm ingredients without their own wiki pages still generate. Permanent material pages are also followed through their monster-drop links when the quest page cannot be found. Temporary source failures are retried twice automatically. Host Hunt, Join, CombatPolicy, turn-in, ledger, and farm-repeat stay in place.

For clickable items, the generated script joins the documented map and invokes map inspection. The bundled FFDec decompiler reads the game's current map SWF. The parser extracts literal pickup calls and quest-bound button metadata, ignoring comments and quoted examples. It selects a unique quest-bound pickup, or a unique unconditional pickup. It does not guess IDs or try an ambiguous set of buttons. Actual inventory ID and quantity must change before the next step or turn-in. Map downloads and decompilation have size/time limits; stopping cancels decompilation. Java is required (the same OpenJDK dependency used by build-flash.sh); on macOS the runtime detects Homebrew OpenJDK automatically.

Bank loading retries and can recognize a complete bank snapshot if its event was missed. An unknown bank is never treated as empty. If it remains unavailable, free quest drops/pickups can run with a visible notice; shop purchases remain blocked. Known banked materials are retrieved instead of farmed.

Planning can be canceled before script launch. Quest state is revalidated after research. If wiki/guides name no map or monster for an objective, Auto-do says so instead of “missing objective routes / no script started.” Arbitrary quest chains, dialogue puzzles, dynamic shop-ID discovery and every possible wiki format are not yet supported. This is structured source discovery and code generation, not an LLM that can reason through any game mechanic.

Validation includes the Wayfarer Potion farm (no item pages, mismatched monster backlinks), independent wiki fixtures for quests 1489 and 4498, no-reward discovery, multiple monster variants, collection locations, bank snapshot completeness, canceled planning, and an authored Flash fixture compiled and decompiled with FFDec. The generated decoder script is also compiled against the installed CoreBots library. These checks do not substitute for a live server quest completion.
